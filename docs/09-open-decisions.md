# Открытые вопросы и дальнейшая детализация

[← Обзор проекта](../README.md)

| ID | Вопрос | Что необходимо зафиксировать | Предлагаемые участники |
| --- | --- | --- | --- |
| D-01 | Состав сценариев | Конкретные 6 сценариев, техники MITRE ATT&CK, критерии безопасного выполнения и запрещённые действия | Эксперт по сценариям, директор ИБ |
| D-02 | SIEM/EDR | Подтвердить допущение MaxPatrol SIEM/EDR, доступность API, состав телеметрии и корреляцию на тестовом контуре | Технический лидер, ИБ, DevSecOps |
| D-03 | Целевая инфраструктура | Версии ОС, типы хостов, разрешённые и запрещённые сегменты, окна проверок | ИТ и ИБ |
| D-04 | Полномочия запуска | US-36 описывает повторный запуск экспертом, а матрица прав разрешает запуск оператору. Определить, инициирует ли эксперт запрос оператору или получает отдельное право | PM, заказчик, ИБ |
| D-05 | Аварийная остановка | Карта требований допускает глобальную остановку администратором, но этого действия нет в ролевой матрице USM. Добавить отдельное полномочие после согласования; определить работу при потере связи и критерий завершения остановки | Технический лидер, ИБ |
| D-06 | Параметры нагрузки | Подтвердить 100 агентов, 5 кампаний, CPU ≤5%, RAM ≤100 МБ; определить профиль нагрузки, оборудование и методику измерений | Технический лидер, QA |
| D-07 | Время отклика | Операционализировать UI ≤3 с для 95% операций, телеметрию ≤60 с, начало остановки ≤30 с; не смешивать начало остановки с её завершением | QA, технический лидер |
| D-08 | Доступ и данные | Подтвердить Keycloak/LDAP/AD, TOTP, PKI, хранение результатов 180 дней и аудита 365 дней, backup, RPO ≤24 ч и RTO ≤4 ч | ИБ, ИТ, DevSecOps |
| D-09 | Источник INT-08 | В реестре не заполнен статус/источник требования о доступе к телеметрии только на чтение. Уточнить источник и статус требования INT-08 | PM, технический лидер |
| D-10 | Детальный план | Подготовить ИСР, бэклог, оценки трудоёмкости, зависимости, ресурсный календарь; сопоставить релизы USM и этапы устава | PM, Product Owner, технический лидер |
| D-11 | Финансовая модель | Проверить ставки, распределение FTE, инфраструктуру и резерв. Исходные 90 млн ₽ остаются ROM-оценкой | PM, спонсор |
| D-12 | Управление рисками | Перенести оценки и владельцев из устава в единый рабочий реестр; определить триггеры, сроки мер, остаточный риск и порядок пересмотра | PM, владельцы рисков |
| D-13 | Приёмка | Разработать программу испытаний, тест-кейсы, критерии критичности дефектов и форму протокола. 136 способов валидации — основа для тестов, но не результаты их выполнения | QA, заказчик, ИБ |
| D-14 | Источники иллюстраций | Уточнить ссылки на исходные материалы существующего продукта, показанного в ТЗ. Сейчас указан только факт заимствования референсов из исходного PDF | Автор кейса |
