## Назначение реестра

Настоящий реестр является рабочим документом этапа детализации требований проекта

**Реестр связывает:**

- Цели и ограничения Устава

- Пользовательские потребности

- USM

- Конкретные требования

- Критерии приемки

- Концептуальное ТЗ

**Реестр предназначен для:**

- Фиксации требований к первой эксплуатационной версии BAS-платформы

- Исключения потери требований при переходе от USM к ТЗ

- Определения приоритетов

- Выявление требований, требующих дополнительного уточнения

- Формирования основы для первоначального бэклога

- Последующей трассировки требований к архитектуре, ИСР, тестам и приемке

<a id="section-02"></a>

## Статусы требований

**В реестре используются следующие статусы:**

| Статус | Значение |
| --- | --- |
| Зафиксировано | Требование зафиксировано в текущей учебной версии; это не подтверждение согласования реальным заказчиком |
| Уточнить | Требование необходимо, но конкретное значение/правило пока не определено |
| Вне Фазы №1 | Не входит в текущие границы |

**В реестре используются следующие источники:**

| Источник | Значение |
| --- | --- |
| Выведено | Требование логически следует из Устава и USM и необходимо для реализации пользовательского сценария |
| Исходное | Требование четко обозначается в Уставе и USM |

**Приоритет:**

- Критический Необходимо для первой эксплуатационной версии и/или критериев успеха Фазы №1

- Высокий Желательно для полноценной внутренней эксплуатации, но может быть уточнено по итогам приоритизации

- Опционально Потенциальное улучшение, не влияющее на базовую приемку Фазы №1

> MaxPatrol SIEM/EDR, Keycloak, параметры нагрузки, хранения и восстановления — проектные допущения версии 0.1. Статус «Зафиксировано» не отменяет необходимость их валидации. См. [открытые вопросы](09-open-decisions.md).

## Ключевые требования приемки Фазы №1

Из общего реестра выделяется следующий набор требований, непосредственно связанный с приемкой первой эксплуатационной версии

**Функциональная готовность**

1. Платформа развернута в согласованном корпоративном контуре

2. Настроены роли и доступы

3. Релизовано управление агентами

4. Доступно не менее 6 утвержденных сценариев

5. Сценарии покрывают три целевых направления - по 2 сценария на каждое

6. Сценарии имеют MITRE ATT&CK маппинг

7. Реализован запуск сценария

8. Реализован контроль выполнения

9. Реализованы остановка и безопасное завершение

10. Реализованы очистка и откат

11. Реализован дашборд

12. Реализована интеграция минимум с одной SIEM

13. Реализована интеграция минимум с одной EDR

14. Реализован сбор и сопоставление результатов симуляции и событий СЗИ

15. Подготовлена отчетность

**Безопасность**

16. Невозможен запуск по запрещенной цели

17. Работают белый и черный списки

18. Есть ограничение параллельных запусков

19. Есть ограничение времени выполнения

20. Есть kill switch

21. Есть обязательное подтверждение оператора

22. Есть запрет потенциально разрушительных действий

23. Работает безопасная обработка потери связи

24. Все действия фиксируются в аудите

25. Компоненты взаимодействуют по защищенному каналу

26. Агенты работают с ограниченными правами

**Качество**

27. Для 100% сценариев протестирован откат

28. Нет критических инцидентов, вызванных платформой

29. Нет случаев недоступности критических продуктовых сервисов из-за BAS

30. Нет критических и блокирующих дефектов в ядре на момент сдачи

31. CPU агента ≤ 5% в пике при штатном выполнении

32. RAM агента не превышает утвержденный лимит

**Эксплуатация**

33. Подготовлена техническая документация

34. Подготовлена пользовательская документация

35. Проведен инструктаж пользователей

36. Определены ответственные за эксплуатацию и сопровождение

37. Подготовлен отчет внутренней апробации

38. Сформирован бэклог дальнейшего развития
